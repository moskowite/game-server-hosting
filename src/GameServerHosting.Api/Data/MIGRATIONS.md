# Entity Framework Core Migrations Guide

This guide explains how to work with Entity Framework Core migrations in the GameServerHosting project.

## Prerequisites

- .NET 8.0 SDK installed
- PostgreSQL database server running
- EF Core CLI tools installed globally (optional but recommended)

## Installing EF Core Tools

Install the EF Core CLI tools globally (if not already installed):

```bash
dotnet tool install --global dotnet-ef
```

Or update if already installed:

```bash
dotnet tool update --global dotnet-ef
```

## Creating a Migration

When you add or modify entity models, create a new migration:

```bash
# Navigate to the API project directory
cd src/GameServerHosting.Api

# Create a new migration
dotnet ef migrations add <MigrationName> --project . --startup-project .

# Example:
dotnet ef migrations add InitialCreate --project . --startup-project .
```

## Applying Migrations

### Update the database with the latest migration:

```bash
cd src/GameServerHosting.Api
dotnet ef database update --project . --startup-project .
```

### Update to a specific migration:

```bash
dotnet ef database update <MigrationName> --project . --startup-project .
```

## Removing a Migration

Remove the last migration (only if not applied to database):

```bash
cd src/GameServerHosting.Api
dotnet ef migrations remove --project . --startup-project .
```

## Viewing Migrations

List all migrations:

```bash
cd src/GameServerHosting.Api
dotnet ef migrations list --project . --startup-project .
```

## Generate SQL Script

Generate SQL script for a migration without applying it:

```bash
cd src/GameServerHosting.Api
dotnet ef migrations script --project . --startup-project .

# Generate script for specific migration range
dotnet ef migrations script <FromMigration> <ToMigration> --project . --startup-project .
```

## Connection String Configuration

The connection string is configured in:
- `appsettings.json` - Production/default settings
- `appsettings.Development.json` - Development environment

Make sure to update the connection string with your PostgreSQL credentials:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Database=gameserverhosting_dev;Username=postgres;Password=postgres"
  }
}
```

## Best Practices

1. **Always create a migration** when you modify entity models
2. **Review generated migration code** before applying to ensure correctness
3. **Use descriptive migration names** that explain what changed (e.g., `AddUserAuthenticationTables`)
4. **Never modify applied migrations** - create a new migration instead
5. **Keep migrations in source control** to track database schema evolution
6. **Test migrations** in development before applying to production
7. **Generate SQL scripts** for production deployments rather than running migrations directly

## Troubleshooting

### Migration Tool Not Found

If you get "dotnet ef command not found":
```bash
dotnet tool install --global dotnet-ef
```

### Build Errors

If you encounter build errors, ensure all packages are restored:
```bash
dotnet restore
dotnet build
```

### Connection Issues

If you can't connect to the database:
1. Verify PostgreSQL is running
2. Check connection string credentials
3. Ensure the database exists (or let EF create it)
4. Check firewall settings

## Migration Folder Structure

Migrations are stored in `/src/GameServerHosting.Api/Data/Migrations/` directory and are automatically generated by EF Core tools.
